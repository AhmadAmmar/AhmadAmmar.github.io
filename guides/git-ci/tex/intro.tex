Research code and documents go wrong in quiet ways: a number typed by hand, a figure from last month\textquotesingle s data, a script that only ran on one laptop. This guide explains the tools that catch those faults, starting from nothing.

It\textquotesingle s based on what I built for my own work, including real mistakes these tools caught. You can see them working in the \href{https://github.com/AhmadAmmar/marxist-economics}{pamphlet project}\footnote{\texttt{https://github.com/AhmadAmmar/marxist-economics}} and its \href{https://ahmadammar.github.io/marxist-economics/how-it-works/}{build guide}\footnote{\texttt{https://ahmadammar.github.io/marxist-economics/how-it-works/}}.

\section{What you will learn}\label{what-you-will-learn}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Git} records every version, so that you can go back to any point.
\item
  \textbf{GitHub} shares work, and lets people report problems and suggest changes.
\item
  \textbf{Tests} check that the code still gives the right answers.
\item
  \textbf{Continuous integration} runs those checks by itself on every change.
\item
  \textbf{Pipelines} rebuild everything from the sources, so that nothing drifts apart.
\item
  \textbf{Backups and releases} protect what matters.
\end{enumerate}
